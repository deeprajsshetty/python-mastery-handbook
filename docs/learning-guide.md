# 🧠 Learning Guide: How to Get the Most From This Handbook

## The daily loop (60–90 minutes)

1. **Read** the day's `README.md`. Do the 🟢 sections first and type every snippet yourself. Don't copy and paste.
2. **Run** the files in `examples/`, then change something in each one and predict the output before you run it again.
3. **Practise**: try every file in `exercises/` *before* you open `solutions/`.
4. **Build** the project, starting with `v1`. Look at `v2` and `v3` only after your own version works.
5. **Check** your understanding with `quiz.md` and `pytest`.
6. **Review** the `cheatsheet.md` the next morning. Spaced repetition makes it stick.

## Principles that work

- **Consistency beats intensity.** 1 hour every day is better than 7 hours on Sunday.
- **Struggle productively.** Spend about 20 minutes stuck before you look at a hint. The effort is where the learning happens.
- **Read error messages from the bottom up.** The last line tells you *what* went wrong, and the line above it tells you *where*.
- **Explain it out loud.** If you can't explain a concept to a friend (or a rubber duck), go back and review it.
- **Build beyond the brief.** Every project has an "extend it" section. Do at least one extension.
- **Keep a coding journal.** Write down one thing you learned and one thing that confused you each day.
  The printable notebook sheets in `0003-download-resource-tips/` work well for this.
- **Commit daily.** Your GitHub history is your proof of progress.

## When you're stuck

1. Re-read the error message slowly.
2. Add `print()` calls to see what your variables actually hold.
3. Shrink the problem: remove code until the bug disappears, and the last thing you removed is the cause.
4. Search the exact error text.
5. Only then look at the solution, and afterwards rewrite it from memory without looking.
